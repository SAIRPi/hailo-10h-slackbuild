# INITIAL APPROACH

First attempt was a straight build of HailoRT on a running Slackware
AArch64 system. cmake 4.3.x killed it immediately with:

  CMake Error at hailort/common/genai/serializer/CMakeLists.txt:5
  (protobuf_generate_cpp): Unknown CMake command "protobuf_generate_cpp".

We decided to build inside a chroot environment to fully isolate the
build environment from the host system.

The chroot approach was the right decision. It enabled us to work very
quickly and iron out any issues that arose. All totally separate and
independent of the running host system. 

See HAILO_BUILD_DEV_DOC.txt for the full technical breakdown of all
issues, patches, and cmake flag decisions.


# CHROOT BUILD ENVIRONMENT

Chroot: /tmp/sairpi-chroot

The package list in chroot-pkg-forge.sh was built iteratively. We started
with base packages, added missing commands and libraries as they surfaced
during testing. This process took approx. 8-9 days.


# BUILD ARCHITECTURE

Two-stage build process:

  STAGE 1 - SAIRPi.SlackBuild (HOSTNAME 'maia' -  Raspberry Pi 5)
  Downloads all source, fetches Slackware packages, constructs and
  populates the chroot, then invokes Stage 2.

  STAGE 2 - hailo.SlackBuild (inside /tmp/sairpi-chroot)
  Builds cmake 3.31.12, RPi Linux kernel, HailoRT runtime libraries,
  HailoRT PCIe and NNC kernel drivers, RPi boot firmware package.


# KERNEL AND FIRMWARE

Kernel branch  : rpi-6.18.y  (next LTS, currently tracked by Slackware)
Kernel defconfig: bcm2712_defconfig (Pi 5 base config - under review)
Firmware branch: next (6.18.x not in master yet - switch when it is)
